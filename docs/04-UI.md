# 04 — Interface : écrans, parcours, textes, design

Interface en **français**, code en anglais. Toutes les chaînes visibles passent par `t('clé')` (`src/lib/i18n/fr.ts`). Mobile d'abord (révision), PC ensuite (création).

## 1. Navigation

Routeur par hash (`#/…`) pour rester compatible avec un hébergement statique sans réécriture d'URL. Barre de navigation basse sur mobile (4 entrées), latérale sur ≥ 900 px.

| Route | Écran | Rôle |
|---|---|---|
| `#/` | Accueil | Compteurs du jour, bouton principal « Réviser aujourd'hui », liste des paquets avec dues, rappel de sauvegarde |
| `#/review?deck=…` | Révision | Séance (tous paquets ou un paquet) |
| `#/decks/:id` | Paquet | Détails, paramètres, actions, sous-paquets |
| `#/cards?deck=&q=&tag=&state=` | Navigateur | Tableau des cartes, filtres, actions groupées |
| `#/notes/new?deck=`, `#/notes/:id` | Éditeur | Création / édition d'une note |
| `#/import` | Import | CSV, `.apkg`, sauvegarde |
| `#/stats?deck=` | Statistiques | Voir SPEC 5.6 |
| `#/settings` | Paramètres | Voir SPEC 5.7 |

## 2. Parcours clés

### 2.1 Premier lancement
Écran d'accueil vide avec trois choix : « Créer un paquet », « Importer (CSV, Anki) », « Essayer avec un paquet d'exemple » (charge `data/samples/departements.csv`, embarqué dans le bundle via `import csv from '../../data/samples/departements.csv?raw'` puis passé à l'importateur CSV). Une seule phrase d'explication de la méthode, pas de tutoriel bloquant. Demande de persistance du stockage après la première carte créée (message : « Autoriser Recto à conserver vos cartes même si l'espace est faible »).

### 2.2 Séance de révision
1. Recto (question). Pour Leitner avec `sideFlipped`, c'est le verso qui sert de question ; un petit indicateur « ↔ » le signale.
2. Bouton « Afficher la réponse » (pleine largeur, bas d'écran). Si `typedAnswer` : champ de saisie au-dessus, Entrée valide et affiche.
3. Réponse : recto, séparateur, verso, Extra ; comparaison colorée si réponse tapée (une formule s'y tape sans ses délimiteurs, `x^2` pour `\(x^2\)`, ou telle qu'écrite, délimiteurs compris).
4. Boutons de notation (bas d'écran, hauteur ≥ 56 px) avec l'intervalle prévu en petit :
   - FSRS 4 : `Encore` · `Difficile` · `Bien` · `Facile` (touches 1–4)
   - FSRS 2 : `Encore` · `Bien` (1–2, Espace = Bien)
   - Leitner : `Oublié` · `Réussi` · `Sûr` (1–3) — sous chaque bouton, le compartiment cible et l'échéance : « → C1 · demain », « → C3 · dans 7 j » (`scheduler.boxTarget`)
5. Menu « ⋯ » : Annuler (Ctrl+Z), Modifier (E), Suspendre, Retirer (désactivé si P7 non satisfait, avec infobulle « disponible après 3 réussites espacées »), Drapeau, Infos.
6. Fin : résumé + bouton « Retour à l'accueil ». Si des cartes en apprentissage restent dues dans < 30 min, proposer « Attendre » / « Terminer ».

Gestes mobiles : tap pour afficher, balayage gauche/droite désactivé par défaut (erreurs fréquentes), option dans Paramètres.

### 2.3 Créer une note
Formulaire : Paquet (sélecteur, mémorise le dernier), Type (`Basique`, `Basique + inverse`, `Texte à trous`), champs, Tags, Source. Aperçu en direct de la ou des cartes générées. Avertissements P8 sous le champ concerné. Boutons : « Ajouter » (reste sur le formulaire vidé, focus sur Recto), « Ajouter et fermer ». Raccourcis : Ctrl+Entrée = Ajouter, Ctrl+Maj+C = insérer un trou sur la sélection (`{{c1::…}}` avec numéro auto-incrémenté).

Médias : bouton « Image » (fichier / coller / glisser), « Audio » (fichier / enregistrer avec compteur), vignette avec bouton supprimer et champ « texte alternatif ».

### 2.4 Import CSV
Étapes : fichier → aperçu et mappage (colonnes détectées, choix du type, paquet cible, doublons) → rapport (n notes créées, ignorées, erreurs par ligne). Tout en une page à sections dépliables, pas d'assistant multi-écrans.

### 2.5 Import `.apkg`
Fichier → analyse (nom des paquets, nombre de notes/cartes/médias, modèles reconnus, taille) → options (importer dans un nouveau paquet « Nom Anki » / fusionner, importer l'historique de révisions, planificateur cible) → progression (par lot de 500 notes) → rapport avec les modèles convertis en `basic`.

## 4. Design

Sobre, lisible, sans gamification. Le contenu de la carte est le seul élément mis en avant.

- **Typographie** : police système (`system-ui`) pour l'interface ; contenu des cartes en 20 px mobile / 24 px desktop, réglable (`fontScale`). Chiffres tabulaires dans les compteurs.
- **Couleurs** (tokens CSS dans `app.css`, thèmes clair/sombre via `prefers-color-scheme` et attribut `data-theme`) : fond, surface, texte, texte secondaire, accent (une seule teinte), et quatre couleurs de notation stables : Encore/Oublié rouge sourd, Difficile orange, Bien/Réussi vert, Facile/Sûr bleu. Contraste AA partout.
- **Espacement** : échelle 4 px ; boutons de notation 56 px de haut ; zone de contenu max 720 px.
- **Mouvement** : transitions ≤ 150 ms, aucune animation décorative, `prefers-reduced-motion` respecté.
- **Icônes** : un petit jeu SVG inline (≤ 20 icônes), pas de bibliothèque.
- **Formules** : `\( … \)` (en ligne) et `\[ … \]` (bloc) rendues par KaTeX (ADR-009) partout où une carte s'affiche (révision, aperçu de l'éditeur), module chargé à la demande et disponible hors ligne ; MathML pour les lecteurs d'écran ; une formule trop large, en ligne ou en bloc, défile seule, jamais la page ; une formule invalide reste en source, soulignée, avec le message « Formule LaTeX invalide » (infobulle, et texte pour les lecteurs d'écran). Le navigateur de cartes affiche la source. Syntaxe dans le champ HTML : un `<` s'écrit tel quel (`\(a<b\)`) sauf s'il ouvre une balise complète ; dans une formule, les balises sont ignorées et les retours à la ligne (`<br>`, `<div>`, `<p>`, `<li>`) comptent comme des espaces ; `&#92;(` affiche `\(` sans ouvrir de formule. Limite : une cloze à l'intérieur d'une formule n'est pas surlignée et son indice y est lu comme du TeX (italique, sans espaces) ; mettre la cloze autour de toute la formule.
- **États** : vide (texte + action), chargement (squelette léger), erreur (message + action de récupération), hors ligne (rien de spécial : tout fonctionne).

## 5. Accessibilité

- Tout est faisable au clavier ; ordre de tabulation logique ; `aria-live="polite"` pour les compteurs et le résultat d'une réponse tapée.
- Boutons avec libellé texte (pas d'icône seule) ; images avec `alt` éditable ; audio avec bouton de relecture visible.
- Cibles ≥ 44 × 44 px ; focus visible (anneau 2 px accent).
- Taille de texte réglable, respect du zoom navigateur (unités `rem`).
